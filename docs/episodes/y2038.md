## Hook

**PIX:** “Wait, UrFavXBF. You're telling me a computer could wake up in nineteen oh one?”  
**UrFavXBF:** “Only some older systems. In twenty thirty-eight, a thirty-two-bit clock can run out of numbers. Watch what happens when its last second ticks forward.”

The video introduces the **Year 2038 problem (Y2K38)**: a signed 32-bit Unix timestamp representing seconds since 1970 reaches **2,147,483,647** at **2038-01-19 03:14:07 UTC**. The next second is **unrepresentable** for that signed type; software may error, misinterpret time or (for wrapping implementations) read **1901-12-13 20:45:52 UTC**. The outcome is implementation dependent, **not an automatic worldwide shutdown**.

## Eight-chapter structure

1. **The Clock that Goes Backward:** gripping countdown to the 2038 rollover.
2. **Why Computers Count Seconds:** the Unix epoch explained with a live timeline.
3. **Why 2,147,483,647 Matters:** signed 32-bit integer and overflow animation.
4. **What Could Actually Break:** legacy software, timestamp-dependent code and embedded systems; bounded risks.
5. **What About Modern Computers?:** time64, mitigations, and what is already fixed.
6. **The Bug That Can Arrive Early:** future date calculations and deployed devices.
7. **How Engineers Fix Time:** testing, migrating timestamps, validation.
8. **Question Everything:** why understanding the boundary matters more than fear.
